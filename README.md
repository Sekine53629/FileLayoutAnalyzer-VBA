# FileLayoutAnalyzer-VBA

受け取ったファイル（帳票の出力、システム連携の CSV・DAT・XML、Excel ブックなど）の**構造**を、**値を出さずに** Word 文書にまとめる Excel VBA マクロです。

取り込み処理や変換処理を作る前に、「どんな形式で、何列あって、各列にどんな種類の値が入っているか」を確かめるために使います。値そのものは報告に載せず、型・桁数・種類の数・書式パターン（`9999/99/99` など）に置き換えます。そのため、患者情報や顧客情報を含むファイルを分析しても、報告はそのまま開発者や AI に渡せます。

医療・薬局のデータ（レセプト関連のファイルなど）を念頭に作っていますが、区切り文字形式・固定長・XML・Excel であれば、業種を問わず使えます。

## できること

| マクロ | 内容 |
| --- | --- |
| `RunFileLayoutAnalysis` | ファイルを選ぶと、構造の報告（`<ファイル名>_構造分析_<日時>.docx`）を同じフォルダに出力する |
| `RunKnownTextSearch` | 中身の分かっている文字列（例: 薬品名）を手がかりに、ファイルの文字コードと、その文字列のある位置を調べる |
| `RunCrossFileAnalysis` | 複数のファイルを選ぶと、ファイルをまたいで同じ値が入っている列（結合キーの候補）を割り出し、対応表（`ファイル間対応_<日時>.docx`）を出力する |

### 構造の報告（`RunFileLayoutAnalysis`）

| 形式 | 報告の内容 |
| --- | --- |
| Excel（xlsx / xlsm / xls / xlsb） | シートごとに、表題・見出し行・データ行・結合セル・表示形式・非表示の行列。見出しの異なる表が続くシートは表ごとに分ける |
| 区切り文字形式（CSV / TSV / DAT など） | 区切り文字・文字コード・改行・引用符・セル内改行を自動で判定し、表題・見出し行・データ行と項目一覧を出す |
| レコード種別ごとに項目数が違う形式 | 先頭項目が種別コードのファイル（レセプト電算の `IR` `RE` `HO` …、ヘッダ `1` + 明細 `2` など）を、ヘッダ・明細・トレーラの層に分け、層ごとの項目一覧と並びを出す |
| 固定長（区切りの無い DAT など） | レコード長と、位置ごとの文字の種類から推定した項目の境界 |
| XML | 要素と属性のパスごとの出現数と、繰り返し要素（レコードの候補） |

項目一覧には、項目ごとに次を載せます。

- 種別（数字・整数・小数・日付・和暦・時刻・文字 など）、桁数、空の数、値の種類の数
- 書式パターン（値の代わり）: `9`=数字、`A`=英大文字、`a`=英小文字、`Ｎ`=全角文字、`ｶ`=半角カナ、`_`=空白。`9(13)` は同じ記号が 13 個続くことを表す
- 備考: キー候補（全件一意）、固定値、コード値の候補、先頭の 0、固定長のバイト数、和暦年月・和暦年月日の形、割合らしい値、個人情報の可能性 など

あわせて、数値の列どうしの関係も出します（値は出さず、関係が成り立つ行の割合だけ）。

- **隠れた割合**: 列 A ÷ 列 B（点数と円の違いを考えて ×10 も試す）が 0.7 / 0.8 / 0.9 のような少数の値に集まるか。その割合が、ある区分の列（保険の種別など）で決まるか
- **同じ値・合計・積**: A = B、C = A + B、C = A × B（数量 × 単価 = 金額 など）

### 文字コード

BOM・UTF-8・Shift_JIS・EUC-JP・JIS（ISO-2022-JP）・UTF-16 を自動で判定します。Shift_JIS の半角カナだけのファイルも見分けます。どれにも当てはまらないとき（汎用機の漢字コードなど）は、報告に「文字コードの手がかり」の欄（0x80 以上のバイトの範囲、各文字コードとしての妥当性、制御コードの数、推定）を載せます。

CSV は Excel で開かずに自前で読むので、先頭の 0 や長いコードが数値に化けません。

### ファイル間の対応表（`RunCrossFileAnalysis`）

- 列の手がかり: 検証番号が合う 8 桁（保険者番号・公費負担者番号の形）・7 桁（受給者番号などの形）、和暦年月・和暦年月日、西暦の日付、連番、長さが一定で全件一意の番号
- 結合キーの候補: 共通の値の数と、それぞれの列の値のうち共通の値の割合。1 から振った連番どうしの一致は「偶然の可能性が高い」として下位に回す
- ファイルの組ごとの結び方の要約
- 対象は区切り文字形式（CSV など）だけ

## 個人情報の扱い

- 報告にはセルの値を載せません。載るのは、見出し（ラベル）、レコード種別コード、XML の要素名と属性名、表題の行（数字は `9` に置き換える）だけです。
- 表題に店舗名などの固有名詞が含まれていれば、そのまま載ります。報告を外に渡す前に、表題の欄を確認してください。
- 見出し行を誤って判定すると、データ行がラベルとして載るおそれがあります。報告の「見出し行」が正しいかも確認してください。
- 値の種類の数や、ファイル間の共通の値は、メモリ上の辞書で数えるだけで、外には出しません。

## 動作環境

- Windows 版の Excel（2010 以降）
- Word（報告を `.docx` にするため。無い場合は `.txt` で出力します）
- 参照設定は不要です（Word・ADODB・MSXML・Scripting は実行時に読み込みます）

## セットアップ

1. Excel で新しいブックを開き、`Alt` + `F11` で VBE を開きます。
2. 「挿入」→「標準モジュール」で 10 個のモジュールを作り、`modules/` の各 `.bas` の中身を**コピー＆ペースト**します。1 行目の `Attribute VB_Name = ...` は除き、モジュール名をファイル名と同じにしてください。
   - `ErrorLogger` / `TextFileReader` / `GridAnalyzer` / `FixedLengthAnalyzer` / `XmlAnalyzer` / `WordReportWriter` / `RelationFinder` / `KnownTextFinder` / `CrossFileAnalyzer` / `FileLayoutAnalyzer`
   - `.bas` は UTF-8 で保存しているため、VBE の「ファイルのインポート」を使うと日本語が化けます。コピー＆ペーストで取り込んでください。
3. マクロ有効ブック（`.xlsm`）として保存します。

## 使い方

1. `Alt` + `F8` から `RunFileLayoutAnalysis` を実行します。
2. 分析するファイルを選びます（`Ctrl` / `Shift` で複数選択できます）。
3. 各ファイルと同じフォルダに報告の Word 文書が出力され、終わると出力先の一覧が表示されます。

- Word は裏で起動して閉じます（1 ファイルあたり数秒かかります）。既に開いている Word に繋がった場合は、利用者の文書や画面には触れません。
- Excel ブックは読み取り専用で開き、保存せずに閉じます。既に開いているブックはそのまま使います。
- 1 つの表で解析するのは、先頭 100,000 行までです。
- 他のマクロから使う場合は、`FileLayoutAnalyzer.AnalyzeFile(パス)`（報告のパスを返す）、`KnownTextFinder.FindKnownText(パス, 文字列)`（結果の文を返す）、`CrossFileAnalyzer.AnalyzeFileSet(パスを | で区切った文字列)`（報告のパスを返す）を呼んでください。

### ログ

実行ログとエラーログは `C:\VBAErrorLogs\ErrorLog_yyyymmdd.csv` に出力されます（`ErrorLogger.bas`）。保存先を変えたい場合は、`ErrorLogger.bas` の `LOG_DIR` を書き換えてください。

## 判定の限界

- 固定長の項目の境界は「文字の種類が変わる位置」で推定します。数字の項目が続く場合（日付 8 桁 + コード 5 桁 など）は 1 つにまとまるので、レイアウト定義書と突き合わせてください。
- 改行の無い固定長は、レコード長を判別できません。
- 汎用機の漢字コード（JEF・KEIS・IBM 漢字など）は文字に戻せません。報告では、その欄を位置と長さだけで示します。
- JSON には対応していません。
- 見出し行は「数字を含まない文字だけの行で、その下に数字を含む行が続く」ことを手がかりに判定します。文字だけの表では見出しを見つけられないことがあります。

## このリポジトリについて

このリポジトリは、非公開で開発しているツールから、Excel に貼り付けるモジュールだけを切り出したものです。`modules/` の `.bas` には、エラーの起きた行を特定するための行番号（10 刻み）が付いています。
